# 2. 连续 3 次仍越界/过密：可见动作清单

## 【契约】确实可见、可调用的相关工具

| 工具 | 用途 |
|---|---|
| `write_page` | 整页重写（可带 `expected_rev`） |
| `batch_edit_pages` | 字符串替换（最小作用域） |
| `add_page` / `delete_page` / `reorder_page` | 续页/删页/移位 |
| `reorder_page` | 调整页序 |
| `instantiate_skill_deck` | 整套换模板（**追加**，不替换） |
| `render_probe` / `screenshot_page` / `read_page` | 诊断 |
| `generate_image` / `edit_image` | 换素材 |

## 动作优先级（【skill】给顺序，【建议】给触发点）

**【skill·guardian §5 原文】**：`增字号/行高 → 加真实内容 → 改行列 → 拆页`
**【skill·guardian §1 原文】**：「内容放不下时：裁减、拆分或换表达，**不得靠缩小字号硬塞**」

**3 次失败后的建议路由（【建议】）**：

```
第1次失败 → 改 CSS（batch_edit_pages 或 write_page）
第2次失败 → 改行列/骨架（write_page）
第3次失败 → 停止局部微调，进入结构性动作：
   a) 续页（add_page）——内容过多
   b) 换版式/母版（instantiate_skill_deck 换一套，或 write_page 换骨架）
   c) 精简文案（回文稿层裁减）
   d) 换素材（图不匹配导致挤压时）
```

**【建议】停止局部微调的判据**：
- 同一页**第 3 次**仍报同一条高危规则 → **停止逐点打补丁**；
- 因为事实是**"这页的内容量与该骨架不匹配"**，属**结构性冲突**，非 CSS 可解；
- **保底**：整页 `write_page` 后仍不达标 → **克隆同母版首现页**重填（牺牲个性保一致）。

**【未知】**：是否有自动"换模板"能力——工具层面只有 `instantiate_skill_deck`（追加），**没有"替换/切换模板"的入参**，所以"换模板"需手动组合删除+追加。**不编造**。

# 3. 「完成」是如何判定的

## 3.1 我实际能依赖的判定层

| 层 | 内容 | 性质 |
|---|---|---|
| **文件生成** | 页面落库、✓ completed | 【契约】 |
| **DOM/几何错误** | `render_probe` 8 规则，高危清零 | 【契约】机器实测 |
| **渲染失败** | `resource_failed`（裂图/404） | 【契约】 |
| **视觉判断** | `screenshot_page` + 主 Agent 目检 | 主观 |
| **交付注释** | 每页自检注释存在 | 【skill·guardian §7】 |

## 3.2 **没有独立最终验收机制**

**明确回答**：
- **【契约】** 没有任何"整册验收""完成检查"工具；
- **【契约】** `render_probe` **单次 ≤12 页**，**无跨页规则**——它只给**页内**事实；
- **【skill】** guardian §7 的"交付记录"是**生成方写注释**（自报），**非独立校验**；
- **【skill】** guardian §6 明言「无渲染能力时……**不得把未验证项报为通过**」——反证：**没有能自动判定"通过"的机制**，只能靠**是否跑了验证**。

## 3.3 所以真实的"完成"是【建议·组合】

```
完成 = ① 所有页 render_probe 高危清零
     + ② 无 resource_failed
     + ③ 每页有自检注释
     + ④ 主 Agent 视觉抽查（非全量）
     + ⑤ 跨页一致性由主 Agent 自持基准比对（人工规则）
```

**【未知】**：引擎侧是否在"全部页面生成完"时有隐式门控——**不可见，无契约**。

**一句话**：**「完成」目前是"我按规则判定的收敛"，不是"系统宣告通过"。** 我不会把后四步当成"已有自动机制"来宣称。
