# 2. 三场景成本区间

**单价假设（【假设·非真实】，参考行业区间）**：文本输入 ¥3/百万t、输出 ¥15/百万t；生图 ¥0.3-1.0/张；视觉模型同文本；`probe`/截图 **credits，兑换率未知 → 不计入**。

| 场景 | 低 | 典型 | 多返修(2×) | 计费构成 |
|---|---|---|---|---|
| ① 20页+4图 | ¥4 | **¥9** | ¥22 | 文本¥3-8 + 生图¥1.2-4 |

**公式**：
```
总价 = Σ(输入万t × 输入单价) + Σ(输出万t × 输出单价)
     + 生图张数 × 单张价 + (probe/截图/vision 未知项)
```

**首次生成 vs 后续优化**：上表为**首次**。后续优化**只重跑脏页**——若改 5 页，成本约为整册的 **10-20%**；若改 `theme.css`→**全册失效**，≈ 重做一次。

# 3. 重复上下文 / 缓存 / 并发

- **同一整册 HTML/工具/skill 上下文反复发送**：**这是最大成本杠杆**。若引擎每页都注入全册上下文，输入 token **线性膨胀**，成本可放大 **2-5×**。我**不会**主动重发整册（只传 brief 文本）。
- **缓存**：是否命中 prompt cache **【未知】**；若命中，输入单价通常大幅下降。
- **并发**：`generate_image` 并行**按张计费**（张数不变→总额不变）；并发**不改变**生图单价。

---

# 4. 我的检查策略（如实说）

| 层 | 【契约】 | 【skill】 | 【建议】我的常规做法 |
|---|---|---|---|
| 每页 probe | 支持 | 逐页自检 | **每页跑**（成本低、收益高） |
| 视觉检查 | 支持 | **每 3-5 页** | **抽样 4-6 / 11-14 次**，非逐页 |
