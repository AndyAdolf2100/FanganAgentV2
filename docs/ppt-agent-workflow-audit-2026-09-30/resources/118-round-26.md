## 回复原文

# 1. 双模式共用内核

**可行**。共用的应是"**流水线与工具调用序列**"，分开的是"**约束策略**"。不要共用版式。

**最小公共数据协议（建议）**
```
{ canvas, slide_id, role(cover/section/ending/body),
  content_source(文稿锚点),
  constraints{ locked_regions[], editable_regions[], palette, font_whitelist, min_font_size },
  mode: enterprise|generic }
```
- 内容项：`{id, kind(text/image/chart), src_anchor, capacity{max_chars,max_lines}}`

**必须分开**：
- **enterprise**：`locked_regions` 非空、palette 白名单强校验、正文字号下限、溢出策略可配、禁改 Logo/背景/品牌色。
- **generic**：只校主题一致性（主辅色、字体族、画布），无区域锁。
- **两者共用**：渲染/probe/截图/修复循环、模块→骨架分配。
- 【契约】无 mode 入参 → 靠 brief 文本传约束。【未知】引擎是否原生支持双模式。

# 2. A–F 先修哪三项

**先修 B、C、F。**

- **B（整册重渲染）**：修复成本放大器，不先修则 A/C 的迭代都极慢。改**脏页重渲染**。
- **C（候选覆盖正式 plan）**：**数据安全**问题，比视觉缺陷优先——覆盖后再回滚会污染版本链。
- **F（生图未接通）**：企业模式的核心缺口，直接决定成品质量下限。

后修 A/D/E：
- **A**：是 B/C 修好后才划算的问题（多次改 CSS 超界，本质是"内容量与骨架不匹配"，不是 CSS 可解）；
- **D**：规则阈值问题（见 §5）；
- **E**：需求开关问题（摘要 vs 全文），非技术缺陷。

**升级路径（不删改原稿）**
```
① 重排（框内换行/字号区间）→ 失败
② 换正文变体（同套版式内的另一排布）→ 失败
③ 重分析区域（重算 bounds/容量，扩大或改用 image_slot/chart_slot）→ 仍失败
④ 明确续页（add_page，显式告知页数）
```
**禁止**：无限微调；**静默精简**（精简必须显式记录被删项与理由）。

# 3. 双层 JSON 是否必须

**不能确认。** 【契约】`generate_page(work_id, page_index, title, brief, image_urls?)`——`brief` 是**字符串**；`write_page(page_index, content, work_id, ...)`——`content` 是 **HTML 字符串**。**签名层面不存在强制 JSON 包裹**；是否在传输层再套一层 JSON 我**不可见**，不假称。

**建议：设计元信息 JSON + 独立完整 HTML 制品**——值得做，能显著减少转义返工：
- 元信息（constraints/容量/mode）走结构体，HTML 走**独立制品**，两者以 `slide_id` 关联；
- 收益：HTML 不必塞进 JSON 字符串值，消除引号/换行转义失败；
- 【未知】远端是否已如此实现——**我不假定**。

# 4. 候选目录 + CAS + 冻结的盲点

**比先写后回滚好，但有盲点：**
1. **依赖图不全**：CSS 变量/共享主题/字体一旦变，**依赖它的所有页**都失效，不止"修复页+直接依赖页"。→ 需**全局资产 → 页**的反向索引。
2. **CAS 提交的原子性**：多页同批提交，**page.rev 会逐个变化**（【契约】`expected_rev` 是**单页**锁），跨页事务不成立 → 需批次版本号自行管理。
3. **冻结后仍可漂移**：冻结只是快照，**改主题/字体后旧检查全部作废**。

**应使旧检查失效的变化（建议）**：
| 变化 | 失效范围 |
|---|---|
| `theme.css` 变量（色/字号） | **全册** probe + 截图 + 一致性 |
| 字体族/`sourceFont` 回落 | **全册**（度量变） |
| 画布尺寸 | **全册** |
| 资产（图片）替换 | 仅**引用该资产的页** |
| 硬件/浏览器渲染环境 | **全册**（截图不可比） |

# 5. 问题台账与可读性判据

**台账结构（建议）**
```
{ issue_id, page, rule_or_criteria, severity, evidence{bbox,像素}, category,
  status(open/fixed/wontfix/UNVERIFIED), fixed_by, recheck_result }
```
- 关键：**`UNVERIFIED` 独立成态**，不得并入通过（【skill·guardian §6】"不得把未验证项报为通过"）。

**真实缺陷 vs 风格偏好**
- **真实缺陷（可判）**：短标签在圆圈内断两行——**属真实缺陷**，判据是"语义单元被拆行"：`label` 内出现强制换行且原标签为单一语义 token；
- **风格偏好（不可自动判）**：装饰密度、留白多少、颜色冷暖。

**D 的规则建议**：把"短标签断行"升为**独立规则**——判据：标签字符数 < N 且渲染高度 > 单行高度 × 1.5；**severity 至少 medium，不得 low 放行**。【未知】平台是否已有此规则（现 8 条中无）。

**独立终审模型应收到**：① 页面截图 + ② 该页 `render_probe` 原始输出 + ③ 该页 constraints/容量上限 + ④ 该页内容锚点（证明文字未丢）——**不给**生成方的自评结论（防顺从）。审核目标：**只报缺陷，不改写**。
