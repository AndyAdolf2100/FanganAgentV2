# 企业 PPT 检查加速（2026-10-08）

## 当前策略：按页面变化复审

按用户进一步确认的要求，取消同一页面版本的“初审通过后再付费独立终审”。页面首次完成完整视觉检查；修复后检查变化页面；冻结版本验收核对已有证据，补查缺失或失效的页面。全册浏览器检查、整册 GLM 审查和导出一致性检查继续保留。

视觉调度允许多个组同时等待结果，所有单图请求共用一个有界线程池。旧实现仅能并发检查同组续页和最终整册；50 个组各 1 页时，初审仍串行。本次跨组调度解除这一等待瓶颈。

- 默认同时检查 5 张，每个请求仍只有 1 张图片；配置范围 1–10。
- GLM 生成/修复、浏览器渲染、版本提交和进度回写在调用线程串行执行。生成下一组可以与上一组视觉等待重叠，避免多个线程同时修改稿件。
- 初审、修复复查及冻结版本补查使用同一调度实现；跨组和同组续页不会各开一层池而导致并发数相乘。
- 冻结版本可以复用当前已提交页面的初审或修复复查证据，保留原始审查阶段与来源，不把复用记录描述为新发生的一次独立终审。
- 复用同时核对 HTML/版本、截图、浏览器测量、模型与审查规则。截图、测量或模型规则变化，即使 HTML 没变也要复审；旧报告缺少新指纹或证据不完整时需要补查。仅全册页码移动不代表页面视觉发生变化。
- 原问题仍需逐项关闭；新增反馈及变化后的验证目标不能凭旧的普通通过结论跳过复验。未解决、无法确认或缺失的证据继续阻止交付。
- 预算停止改为单向 Event；普通错误不能覆盖预算错误。未开始的页面明确标记未验证，在途请求收齐后保存，不能据此认定通过。
- 页面输出顺序保持稳定；图片观察可以乱序完成，不会因此重新排列成稿。

普通网页 PPT 的入口、生成及验收流程未改；本次跨组调度用于企业 v5。

## 调用数量与提速边界

全新 50 页且无缓存、无修复时，基础页面视觉调用为 **50 次**。假定后续只改 1 页、该页首次复查即通过，且其余页面证据仍有效，则仅额外 **1 次**，不重查另外 49 页，也不在冻结验收时再次重复检查该页。模板理解、生成图片的素材验收等调用另计。

实际调用数可能因多轮修复、截图或测量变化、模型规则更新、缺失证据及新增问题复验而增加。“只复查变化页”不表示仅比较 HTML，也不表示省略最终版本与导出结果的核对。

## 配置及生效

在项目 `.env.marketing` 中按需要设置：

```dotenv
MARKETING_VISION_WORKERS=5
```

Compose 已补传该变量；非法或空值回退 5，整数限制在 1–10。Docker 服务运行后，重新创建 API 容器以加载配置和新代码：

```bash
docker compose --env-file .env.marketing -f compose.marketing.yaml up -d --no-deps --force-recreate api
```

执行前确保没有需要保留的在途任务。本次本机 Docker daemon 无法连接，18080 也未监听，因此未执行服务切换、未做真实模型端到端验收。
