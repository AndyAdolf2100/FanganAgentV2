## 根因：模型生成了HTML，但约束给错了

读取实际 `template_contract` 后确认：

1. 第8页的模型将圆环、色条、阴影列为受保护品牌元素；第21页将商务示例照片及边框锁定；第51页将中央管道树锁定。这些约束会直接阻止随后自由美化。
2. 第12页的自由区是 `{x:330,y:120,width:830,height:520}`。左侧空白不是单纯CSS偶发错误，而是模型提出的区域约束被后续流程强制执行。
3. 浏览器检查56页通过，但原任务视觉状态为 `needs_review`。原视觉报告标记1、8、16、49、51、52、53页；8次修复尝试全部回退。不能将“completed”解读为美观验收通过。
4. 原批量视觉报告将第21页评为“清晰、无明显问题”；对第48页还描述为“带数字9”，与实际截图不符。审美与可见性仍需要独立检查。

## 本轮代码调整

- `presentation_vision.py`：兼容入口内部强制逐页请求；首次截图审查、修复后复查都每次仅一个成品页。对应模板/风格参考图仍可随本页附带，不把其他成品页合并进去。
- 普通流程、企业完整HTML流程及保留的旧企业入口均改为逐页调用；缓存和预算按实际请求计数，历史账本不重置。
- 企业修复的预估复查金额按改动页数计算。前端分别显示逐页审查、模型修复、修复后逐页复查进度。
- 企业正文修复增加 `select_body_repair_template`：由项目文本模型判断保留、换用同一已发布模板中的其他body变体，或重新分析约束。固定页不能通过此工具改成正文模板。
- 换模板后重新使用对应参考、约束与不可变来源生成完整HTML；旧模板资源别名不跨模板沿用。仍执行来源、品牌、浏览器和逐页视觉复查，失败保留上一版。修订记录支持断点恢复。
- 企业Skill强调中央圆环、流程图、管道树、商务示例照片通常属于可调整的内容素材，不应以“90%沿用”为由全部固定；人工标记品牌仍保留。
- 视觉提示补充页型差异：章节页不因没有正文而判空洞；必要章节号缺失不能降为单纯风格偏好；不能根据标题猜测徽章中有数字。

这些工具与HTML生成仍由项目Agent执行。Codex负责代码和独立截图审查，没有手工设计或改写这份成品HTML。
