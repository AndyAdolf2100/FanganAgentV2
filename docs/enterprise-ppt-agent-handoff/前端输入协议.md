# 前端需要交付的数据

> 2026-09-30更新：企业v5核心已接入，实际实现与限制以[本轮v5实施与验收](v5实施与验收.md)为准。本文保留初版分析脉络，拟议能力不能视作已验收。

前端的PPTX拆分、自动打标、人工调整规则由你集成。后端入口只消费发布后的结构化快照，不接管拆分和标注UI。

## 当前兼容协议

当前保存入口：`PUT /api/enterprise-templates/{template_id}`。完整有效样例见 [frontend-template.json](resources/examples/frontend-template.json)。当前权威校验见 [uploaded_templates.py](resources/source/marketing/marketing_agent/enterprise/uploaded_templates.py) 和 [service.py](resources/source/marketing/marketing_agent/enterprise/service.py)。

| 层级 | 关键字段 | 约定 |
|---|---|---|
| 模板 | `version:1`、`id`、`name` | id为64位小写十六进制；URL与请求体id一致 |
| 画布 | `width`、`height` | 用实际CSS px，比例16:9；不要把PPT的EMU直接传来 |
| 页面 | `pages[]` | 保留完整页序和元素顺序 |
| 页用途 | `role` | cover、contents、section、preface、body、ending、exclude |
| 页面背景 | `background`及已有扩展字段 | 模板背景与正文白底板不能在清洗时丢失 |
| 元素 | `elements[]` | text、image、shape；`x/y/width/height/rotation` |
| 文本 | `paragraphs[].runs[]` | text、size、font、color、bold等；保留分段及文本框内边距 |
| 标签 | `textRole`、`labelSource`、`binding`、`order` | 自动/人工来源必须保留，不把自动fixed等同于人工保护 |
| 图片 | `assets[]` + 元素asset/renderAsset | 本地受控资源；保留裁切、翻转、透明度和资源引用 |
| 矢量/组合效果 | 原有vector、matrix、shadow等 | 不能为了简化数据把品牌图形变成空框 |
| 字体和颜色 | `fonts`、`colors` | 辅助提取主题；实际元素属性仍须保留 |
| 发布 | `reviewAccepted:true`、`published` | 人工核对后发布；published包含revision、name、pages快照 |

当前文字标签包含：title、subtitle、body、itemTitle、itemBody、contentsNumber、contentsItem、contentsSubtitle、sectionNumber、presenter、date、pageNumber、brand、decoration。`advisor` 是生成文稿元信息用途，**不是当前前端textRole词表里的合法值**；如要新增标签，前后端需一起扩展。详见 [template_labels.py](resources/source/marketing/marketing_agent/enterprise/template_labels.py)。

自动标签不构成最终模型合同。现有合同校验会强制保护 `labelSource=manual + textRole=brand` 的文字元素；**对图片/形状提供通用人工锁定标记，是建议补齐的能力，不能声称当前任意fixed都具有同等强制语义。** 建议新增独立的 `user_lock` 协议，但在前后端支持之前不要直接发送未约定字段并期待生效。

## 最容易踩坑的地方

1. 当前 `data-template-element` 使用元素数组零基下标，模板页也用零基索引。成品页号、视觉反馈和UI用一基页码。必须明确转换，不能混用。
2. 发布版本内不要重新排序/删除元素后继续用旧合同。长期建议使用稳定元素UUID，但当前需要保留数组顺序；UUID扩展要与后端资源别名同步迁移。
3. 标题标签可能误贴在正文中央示例小标题上。模型必须结合位置、视觉、原始HTML判断；前端不要把它们全变成不可变区域。
4. 字体缺失会改变换行和固定文本框适配。前后端需用同一字体包，字体替换必须可见，不能只以本机预览判断服务器结果。
5. 固定背景不是一张遮住所有正文的截图。正文必须能单独重排；原模板图案、logo可以作为资源保留。
6. 发布的是不可变快照。更新模板产生新revision，不覆盖运行中任务引用的版本。
7. “第二页是序言页”是当前模板的用途调整，不是所有上传模板的固定识别规则。只有明确文稿序言才调用preface。

## 交接时推荐额外附带但尚未成为当前API硬契约的内容

- 模板每页原尺寸参考截图与文件hash，方便核对前后端渲染是否一致。
- 源PPTX的hash、解析器版本、字体映射说明。
- 明确的人工品牌保护范围与正文可变区域，记录人工意图而非仅依赖自动分类。
- `element_id → 原PPT页号/shape id` 的映射，便于将错误回显到前端。

这些是适配建议；当前服务仍以原有version1结构为准。同事可以在新协议外层加version2适配层，但应先转换后调用，不应把拟议协议误认为现有接口。

## v5模型标签建议

前端导入解析后，可请求单页自动分析。请求包含`pageIndex`、`totalPages`、`width`、`height`、`page`、`html`、64位`snapshotRevision`。后端只读取快照并返回建议和置信度；前端用相同快照hash检查是否过期再应用，保留manual锁和低置信度待确认项。不会把PPTX拆分迁到后端。
