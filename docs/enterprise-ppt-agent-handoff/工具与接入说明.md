# 工具与接入说明

> 2026-09-30更新：企业v5核心已接入，实际实现与限制以[本轮v5实施与验收](v5实施与验收.md)为准。本文保留初版分析脉络，拟议能力不能视作已验收。

## 路径A：直接使用当前服务

这是最快且行为最清晰的接入方式。前端保持自己的拆分/打标；生成网页PPT的主Agent通过以下粗粒度工具操作服务。服务内部调用GLM、浏览器、视觉模型，不需要Codex参与。

| 顺序 | 现有HTTP接口 | 用途 |
|---|---|---|
| 1 | `PUT /api/enterprise-templates/{id}` | 保存/发布前端模板JSON |
| 2 | `GET /api/enterprise-templates/{id}/check` | 校验模板和字体 |
| 3 | `POST /api/runs/import` | 导入完整Markdown文稿，建立项目 |
| 4 | `POST /api/runs/{run_id}/presentation` | 指定template_id及template_revision生成 |
| 5 | `GET /api/presentations/{job_id}` | 状态及当前阶段 |
| 6 | `GET /api/presentation-drafts/{job_id}` | 草稿页清单与优化标识；由独立preview服务提供 |
| 7 | `GET /api/presentation-drafts/{job_id}/previews/{number}` | 查看已设计的第number页 |
| 8 | `POST /api/presentations/{job_id}/optimize` | 创建同项目的优化版本，可带具体逐页反馈 |
| 9 | `POST /api/presentations/{job_id}/resume-optimization` | 恢复已有优化版本；适用状态由后端检查 |
| 10 | `GET /api/presentations/{job_id}/files/presentation.html` | 导出完成后下载HTML |

`/files/presentation.pptx`、`report.json`、`visual-review.json`等也有对应文件入口。`/api/runs/{run_id}/presentation`获取同项目最新版本。

当前API的任务`completed`不等于审美验收通过。v5已实现`quality_status`、`ready_for_delivery`、`artifacts_available`及`quality-report.json`；只有ready_for_delivery=true才通过全部交付检查。旧任务仍需读取visual_status和报告。

现有API文档快照见 [openapi.json](resources/openapi.json)。草稿服务独立提供，额外协议见 [preview-openapi.json](resources/preview-openapi.json)。若同事部署到远端，需要自行接入团队已有的鉴权、租户隔离及文件访问控制；当前本机服务不能直接充当已完成这些能力的公网服务。

### 直接试用客户端

在本文件夹运行；查询不会生成PPT或调用模型：

```bash
python3 resources/tools/project_ppt_client.py status 40bf3188a3bf430fa448a664ed8a4f4f
python3 resources/tools/project_ppt_client.py draft 40bf3188a3bf430fa448a664ed8a4f4f
```

以下命令会创建任务/可能调用收费模型，应由使用者在自己的项目中主动执行：

```bash
python3 resources/tools/project_ppt_client.py import-manuscript manuscript.md --title 企业方案
python3 resources/tools/project_ppt_client.py generate RUN_ID --template-id TEMPLATE_ID --revision 1
python3 resources/tools/project_ppt_client.py optimize JOB_ID --feedback resources/examples/repair-feedback.json
```

模板保存与发布由你现有前端调用PUT接口；客户端不替你实现标注和发布UI。接口密钥如需鉴权，使用环境变量 `PPT_SERVICE_TOKEN`，不要写入文稿、skill或浏览器页面。

## 路径B：移植后端工具进入同事现有Agent

源码在 [resources/source/marketing](resources/source/marketing)。保持`marketing_agent/`与`presentation/`相邻，当前工具使用相对路径读取skill和渲染器。

| 源文件/入口 | 可迁移职责 | 注意 |
|---|---|---|
| `enterprise/manuscript.py`、`template_html.py` | 语义块、来源、目录和表格验证 | 不能只迁移提示词而丢来源检查 |
| `enterprise/model_html.py::plan_deck` | 模型分页与元信息 | 依赖模板目录与源文稿 |
| `analyze_contract`、`contract_check` | 模型约束分析及校验 | 自动标签是参考；固定合同须版本化 |
| `select_body_repair_template` | 选择更合适的正文变体 | 新变体应重新理解，不能直接套旧合同 |
| `repair_model` | 有限JSON/内容自我纠错 | 保留original_task_feedback与最新候选 |
| `document_check`、`resume_prefix` | 完整HTML和断点复用校验 | 不能只检查是否包含html标签 |
| `enterprise/workflow.py::model_json` | 项目文本模型HTTP适配与响应缓存 | 可替换成同事的GLM客户端 |
| `presentation_agent.py` | 工具轨迹、参考理解、修复决策 | 不是一个隐含Codex调用 |
| `presentation_vision.py` | 单张PNG审查、响应校验、预算 | 默认请求配置按目标账号验证 |
| `presentation_images.py`、`enterprise/assets.py` | 图片生成、参考图编辑、缓存及企业素材规划/验收/纠错 | 复用共享预算；未验收素材不交给HTML模型 |
| `presentation_budget.py` | 跨进程累计预留 | 预留不是真实供应商账单 |
| `presentation/enterprise.mjs` | Chromium真实渲染、截图、探针、PPTX导出 | 依赖Playwright、pptxgenjs和字体 |
| `presentation/charts.mjs`、`enterprise/adaptive.py::chart_spec` | 来源绑定图表与原生图表导出 | 不让生图模型制造图表数字 |
| `presentation_preview.py` | 只读草稿预览 | 不触发生成，单独进程运行 |

源码快照包含旧试填、演示和兼容路径。当前企业新任务以`enterprise_workflow_version=5`进入新流程；部分兼容元数据仍显示`enterprise-model-html-v4`，不能只凭该字段判断是否走v5。不要因为某个模块名字含enterprise就全部接入。模板试填与demo的规则编译器不等于实际模型生成流程。

若完全移植，需由同事实现/接入：持久化任务队列、模板与版本存储、模型适配、对象存储、预算、事件流、运行隔离和导出文件服务。源码快照**不是无需依赖即可一键安装的独立SDK**。

## 依赖与配置

- 当前Python项目要求3.12及以上；依赖见 [pyproject.toml](resources/source/marketing/pyproject.toml)。
- Node依赖按 [package-lock.json](resources/source/marketing/presentation/package-lock.json) 安装；使用Chromium和对应中文字体。
- 文稿已导入后，PPT链路本身可通过受控Python工具执行；不必把整个营销调研工作流迁给同事。
- 当前文本配置：`MARKETING_API_KEY`、`MARKETING_BASE_URL`、`MARKETING_MODEL`。
- 当前图片/视觉配置：`MARKETING_IMAGE_API_KEY`、`MARKETING_IMAGE_BASE_URL`、`MARKETING_IMAGE_MODEL`、`MARKETING_VISION_MODEL`及enabled开关。
- 配额：图片次数、视觉次数、单价预留、合计预算。迁移应显式设置，不沿用测试账号密钥或默认为无限。

模型HTTP请求应保留超时、缓存、错误脱敏和用量记录。网络失败不等于供应商没有计费，不能对图片生成无限自动重试。原始模型回答可保留，但运行日志和交接包不要包含Authorization。

## 目标工具协议与当前实现的区别

[目标工具协议](resources/skills/enterprise-ppt-agent/references/tool-contracts.md)描述完整高质量链路所需的逻辑工具。它们是给同事注册工具时用的契约，不是假称服务现在有同名REST路由。企业生图、候选事务与最终门禁已经接入v5；优先使用路径A验证当前行为，并按本轮验收文档确认仍待验证的范围。

## v5自动分析入口

`POST /api/enterprise-templates/{template_id}/analyze-page`接收前端产生的单页快照，Seed看一张图，GLM返回建议。前端核对snapshotRevision后应用标签，人工品牌锁和冲突不自动覆盖；完成后由前端保存/发布。真实JSON字段请以openapi及源码template_analysis.py、frontend/enterprise/analysis.ts为准。

客户端支持`capabilities`（只读）和`analyze-page TEMPLATE_ID --snapshot snapshot.json`（会调用项目模型），后者不解析PPTX、不直接写标签。
