# 企业模板复用：118 技术交流与本地项目适配评估

日期：2026-09-28。目标：至少沿用企业模板的主要视觉风格，封面、章节页、尾页尽量只替换内容，正文页允许有限布局变化。

调研对象：

- 当前 18080 工作台：`marketing_v2_agent`，PPT 流程 3.0。
- 企业模板项目：`agent-api-master-455fb50c17064d6d222c8af21e2c7a03063bfd8a`，检查的是当前工作区，包含其未提交修改；没有修改该项目文件。
- 118：用户指定会话、codedeck 后端，新增第 22–24 轮技术问答；没有请求生成 PPT、生图、修改页面或导出。交流结束时会话 idle，既有作品仍为同一页。

## 1. 结论

**企业模板项目的数据、导入管理、字段标签、发布版本和固定结构保护机制可以复用。它比当前 18080 的通用母版更接近这次需求，但不能直接接入就承诺与原始 PPTX 达到 90% 保真。**

主要需要补齐两类工作：

1. 导入时的视觉保真：字体、复杂图形、图表和表格可能已经发生替换或缺失。生成时保持导入快照不变，无法弥补导入前后的损失。
2. 内容区的授权：目前正文主要只能在原文字框内排文字，还缺少明确的企业图片槽、图表槽和可组合组件区域。

建议新增企业模板生成分支，复用模板项目的资产与固定外壳保护，结合 18080 的项目模型、图片服务、截图复核、任务管理和导出。不要把整套企业模板当成一张风格参考图，也不要直接送入现有自由页面生成路径。

本文为研究和适配方案，尚未实施接入或新建生产 Skill。

## 2. “90% 沿用样式”应如何落成规则

本报告将这个要求理解为视觉和品牌保真目标，而不是要求“90% 页数必须套模板”，也不是容许随机修改 10% 的品牌元素。

建议将要求拆成：

- **品牌固定项 100% 保持**：Logo、背景、固定装饰、品牌固定文案、指定字体与色板、固定页几何关系。
- **只有授权区域可以变化**：标题、日期、章节号、正文、允许替换的内容图片、允许更新的数据图表。
- **自由范围由模板作者定义**：哪些区域只换字，哪些可重排文字，哪些允许放图或组合企业组件。

不直接承诺一个未经对照验证的“90% 得分”。验收应同时包含原始 PPTX→入库模板、入库模板→生成结果两段检查。

## 3. 向 118 询问后的可靠结论

### 3.1 已披露的能力边界

118 表示，在它当前会话可见的工具和 Skill 范围内，没有找到专门的企业 PPTX 母版保真复用 Skill。现有 `xiaofang-methodology`、`ppt-guardian-pro` 提供品牌素材优先、版式纪律和风格一致性要求，并不等于企业模板导入器。

`parse_files` 的契约允许解析 PPTX，但没有承诺母版、字体和坐标的保真程度。不能因此断言整个 118 平台完全没有 PPTX 母版能力；第一轮的过强表述已经在追问中撤回。

118 的 `instantiate_skill_deck` 消费其模板包，而本地企业模板是 JSON；没有已确认的官方转换器。工具说明中的 `pages/` 与模板包规范的 `deck/.../slides/` 仍存在路径表述矛盾，本次没有通过实际实例化验证。

### 3.2 适合采纳的建议

- 固定页尽量做字段替换，减少模型重新设计的机会。
- 正文可以在固定外壳内，使用明确授权的安全区和企业组件。
- 先选择合适的同套装版式，容量不足再续页；不要靠无限缩字维持页数。
- 样式约束应由宿主代码验证，不能只写在提示词中。
- 使用固定项结构检查，配合同环境截图对照；遮罩可变文字区后，截图差异才有参考价值。

### 3.3 追问中纠正和未照搬的建议

1. **“字符串替换是唯一可靠方式”已撤回。** 本地的字段定位和权限合并也可以保护外壳。稳定字段 ID 比全局字符串替换更容易避免同名文案误伤，但多 span 标题仍需要分段文字分配、字重和颜色保留规则。
2. **“固定项只要 90% 不变”已撤回。** Logo、品牌色等应全部锁定，不能允许其中 10% 随意变化。
3. **“本地完全缺字体和容量数据”已撤回。** 项目已有 fonts/colors、文字框、容量估算、字号下限和溢出重试；真正缺少的是角色化的品牌约束及可配置区域权限。
4. **“正文一律不能新增图片”不适合作为最终需求。** 模板可以明确授权内容图片槽、图表槽；这不代表允许替换 Logo 或背景。
5. 第 24 轮建议把 `text_only` 也允许缩放字号，本报告不采用：固定页仍应保持字体与字号，换行或分段必须遵守模板字段策略。
6. 第 24 轮提到正文段落增删，本报告不把它作为排版工具的默认权限。内容精简取决于独立的文稿模式，排版修复不能擅自删文案和数据。
7. 图片一律 `cover`、面积固定比例等建议不直接升级为硬规则。产品全貌图可要求 `contain` 或主体保护，按槽位策略验收。
8. 对“结构化输出一定更省返工”的判断仍属工程预期，尚无相同原稿下的调用次数对照实验。现有宿主合并已经会还原模型改动的固定外壳，不能说所有外壳变化都会导致整页重试。

完整问答见 [118 交流记录](ppt-research-dialogue.md) 第 22–24 轮。

## 4. 企业模板项目已经实现了什么

### 4.1 模板资产结构

前端类型 `EnterpriseTemplate` 已包含：

| 层级 | 现有字段 | 作用 |
|---|---|---|
| 套装 | `version/id/name/width/height/aspectRatio` | 模板身份与画布 |
| 资源 | `assets[]`，含 ID、MIME 和内嵌资源数据 | 图片等固定资产 |
| 发布 | `published.revision/pages/name` | 已发布版本 |
| 页型 | `role`：cover、contents、section、body、ending、exclude | 页面用途与停用标记 |
| 布局 | `layoutKind`：text、items、comparison、timeline、table 等 | 版式选择提示 |
| 元素 | `id/kind/x/y/width/height/rotation` 等 | 元素及其几何关系 |
| 内容权限 | `binding/textRole/fieldName/order` | 固定或可替换、字段语义和条目配对 |
| 文字 | `paragraphs/runs/textLayout` | 字体、字号、颜色、字重及段落样式 |
| 转曲文字 | `artworkType=outlinedText/artworkTextRole` | 明确授权的文字图形处理 |
| 原始信息 | `sourceFont/fonts/colors/warnings` | 导入信息与降级提示 |

模板管理已提供 PPTX 导入、页型编辑、AI 标签识别、人工修正、字段检查、试填和发布。AI 标签不能代替人工核对：错误标成品牌固定文字的业务文案会原样留在成品里。

### 4.2 当前真正运行的生成方式

当前新建上传模板任务使用 `model-template-html`：

> 文稿块与模板目录 → 模型规划页型和模板页 → 模型输出文字区域 HTML → 宿主合并回原模板 → 内容和固定结构校验 → Chromium 检查 → 发布 HTML。

模型输入包含模板 HTML、字段标签、文字框几何、字体样式、文稿上下文和本页内容。

`preserve_fixed_markup()` 从模型输出中提取授权区域内部内容，写回原模板。背景、图片、图形、外框和全局样式采用原模板，而不是采用模型输出的版本。

`validate_html()` 检查区域权限和模板结构。固定页的 `text-only` 模式保留文字结构和样式；正文 `body-text` 模式允许在框内调整文字排布。

### 4.3 按页型的符合程度

| 页型 | 当前行为 | 与本需求的关系 |
|---|---|---|
| 首页 | 一页，第一位；开放文字，文字结构与样式保持 | 接近要求，可进一步改为稳定字段替换 |
| 尾页 | 一页，最后；开放文字，其他固定 | 接近要求，可进一步减少模型参与 |
| 章节页 | 只开放标题与章节号，其他文案也固定 | 接近要求；原模板副标题必须是可长期保留的内容 |
| 目录页 | 字段填充，可复制同模板续页，保留原样式 | 基础完整，需核对目录标签与容量 |
| 正文页 | 外框不变，框内文字可重排、调整字号和续页 | 符合保守模式，但还不是图文组件自由组合模式 |
| 内容图片、数据图表 | 现有图片多为固定素材，正文新增非文字内容被限制 | 需要显式增加图片槽和图表槽 |

当前固定页仍经过 HTML 模型，并不是全部由程序直接填字段。固定外壳和校验使其受约束，但文字样式、分段和长标题问题仍可能导致重试。

### 4.4 版本与来源检查

发布时保存不可变模板版本，已有任务按 `template_id + revision` 读取快照。草稿编辑不应改变旧任务的引用版本。

系统已有字段合法性和重复检查、来源块完整性、目录完整性、模板示例文案检查、真实浏览器溢出检查和 HTML 校验哈希。

当前文稿模式要求正文原文逐字保留，最多 200 页。这与 18080 的“正文提炼＋备注保留全文”不同，不能在迁移时忽略这个差异。

## 5. 实际模板资产核对与关键缺口

本次只读检查了该项目本地容器 `/app/uploaded-ppt-templates` 中的已发布模板：

| 项目 | 实际记录 |
|---|---|
| 模板 ID 前缀 | `e064fb24d5c7` |
| 发布版本 | v2 |
| 画布 | 1200×675，16:9 |
| 模板页 | 23 页：封面 1、目录 1、章节 4、正文 16、尾页 1 |
| 资源 | 21 项 |
| 文字 run 的实际字体 | 327 项均为 `system-ui` |
| 原字体信息 | 部分保存阿里汉仪智能黑体、思源黑体、Calibri 等；120 项没有 sourceFont |
| 导入警告 | 25 项，包括背景纹理未还原、部分形状降级为矩形等 |

### 5.1 原字体保真没有完成

`parser.ts` 保存 `sourceFont`，实际 `font` 写为 `system-ui`。即使生成结果完全保留该快照，也已经不是原 PPTX 的字体排版。

需要建立企业允许字体、实际可用字体和明确替代策略。字体文件可用性、字形覆盖与使用授权应在模板入库时确定；不能只靠浏览器端检测就认为服务端和 PowerPoint 会用相同字体。

### 5.2 PPTX 导入存在降级

导入器会处理母版和布局继承，但代码明确对图表、表格和嵌入对象给出未自动还原提示，部分纹理、形状和效果也可能近似处理。

入库应先把原始 PPTX 与导入 HTML 对照，修复或确认降级项，再形成“企业已认可”的发布快照。否则后续严格锁定会把错误也锁住。

### 5.3 正文品牌约束仍不够精确

正文文字 HTML 的样式允许列表含 `font-family` 和 `color`。这说明“有字体/色彩元数据”还不等于“生成时只能使用企业允许的字体和颜色”。

建议增加角色→字体、字号区间、品牌色的硬约束，并对计算后的实际样式检查。页面模型与视觉修版都应受同一套约束。

### 5.4 图文、图表和企业组件的权限尚不完整

当前文字区允许列表或表格形式的文字表达，不等于支持新增产品图、原生图表或品牌组件。需要另建授权区域，不应扩大普通文字区域的权限来绕过固定结构保护。

### 5.5 管理服务目前是本地工作台形态

模板文件使用本地目录，管理 API 受 `ENV=docker-local` 限制。它可以作为本地能力基础，但不能直接视为已有企业租户隔离、权限管理和线上资产服务。

## 6. 建议的企业模板权限模型

以下为拟议适配，不是当前已有接口，也不是 118 的官方 schema。

| 区域模式 | 允许修改 | 始终保持 |
|---|---|---|
| `text_only` | 明确字段的文本，按原有段落/span 分配 | 位置、尺寸、字体、字号、颜色、装饰和固定文字 |
| `body_text` | 锁定文案在文字框内排布；按允许范围调整行距和字号 | 外框、企业字体与色板；不得擅自删改数据 |
| `image_slot` | 指定图片槽内替换内容图片，必要时由项目 Agent 调用图片工具 | 槽位、长宽比、裁切策略、主体保护；Logo/背景另行锁定 |
| `chart_slot` | 数据来源支持的图表类型、系列和标签 | 图表边界、企业字体与配色、来源和原始数值 |
| `component_zone` | 安全区内选择并组合已批准的企业组件 | 外壳、组件白名单、间距规则及品牌约束 |

固定页优先走 `text_only`；正文可以按模板逐区域组合其他模式。法规说明等正文可保留严格文字框模式，策略和数据页可以使用组件区。

字段替换应以 `revision + page_id + element_id/field_name` 定位，不能用全文搜索替换同名词。若字段横跨多个不同字重或颜色的 span，需要明确的 segment 分配规则，并验证新文字的容量。

转曲标题若改成真实文字，会失去原字形轮廓与字体无关的保证；只对模板作者明确标注的文字区域开放，并在发布预览中核对新样式。

## 7. 如何接入当前 18080

### 7.1 可直接借用的层

- 模板 JSON、页型和文字语义标签。
- PPTX 导入及其警告信息。
- 企业模板管理 UI 的交互与发布概念。
- 不可变版本快照。
- 文字区域权限合并、固定结构校验。
- 字段容量、来源覆盖、目录和示例文字检查。

这些是可移植的组件与设计，不是可以不处理依赖就直接复制整个模块。

### 7.2 必须适配的层

| 当前差异 | 需要的处理 |
|---|---|
| 18080 只接收 `style_id`，没有企业模板选择参数 | 新增模板模式、模板 ID 与发布版本 |
| 企业模板是 pages/elements/assets；18080 是 narrative plan 与 custom body/css | 使用独立企业模板渲染分支，避免字段硬塞进通用页型 |
| 企业模板支持自身宽高，18080 固定 1280×720 | 保留原画布或明确定义等比例归一化，统一测量和导出单位 |
| 18080 自定义页面会添加统一页脚与主题 CSS | 企业分支保留企业页脚和原主题，不能额外叠加通用页脚或颜色 |
| 企业 HTML 使用 SVG、表格、丰富属性；18080 自定义 HTML 白名单不同 | 复用企业专用渲染与校验，不直接放宽通用页面校验器 |
| 18080 的 PPTX 导出文字目前固定使用 Microsoft YaHei | 导出器读取实际企业字体和样式，验证 PowerPoint 结果 |
| 现有自动修版可重写页面 HTML/CSS | 企业修版只操作授权区域，修后重新检查固定项 |
| 18080 默认围绕 cover/scene1/scene2 策划图片 | 企业分支按允许换图的槽位规划，已有图片和 Logo 不应触发生图 |
| 企业项目强制原文在正文逐字保留 | 显式选择内容模式，不能沿用后悄悄改变 18080 的摘要习惯 |

### 7.3 建议执行链

```text
上传 PPTX / 导入已发布模板 JSON
  → 入库保真预览、字体与警告核对
  → 标注页型、固定项和可编辑区域
  → 检查字段、容量、企业字体色板
  → 发布不可变版本
  → 用户选择文稿、模板版本和内容模式
  → 项目 Agent 在同套装内规划页型与内容
  → 固定页填字段；正文选择企业组件或生成受限文字 HTML
  → 仅在授权图片槽需要时调用项目 Seedream
  → 宿主合并固定外壳
  → 固定项、数据、来源、浏览器检查
  → 视觉模型检查；受权限约束的修复
  → HTML / PPTX 导出与应用内验证
```

### 7.4 内容完整性与视觉保真独立配置

建议使用互斥的 `content_mode = presentation_summary | full_text`，再单独设置是否把完整原稿放入备注。比三个可互相冲突的布尔开关更清楚。

- `presentation_summary`：模型提炼正文，关键事实、预算、KPI 和条件不得改变；完整原稿可保留备注。
- `full_text`：原文逐字进入正文，容量不足允许续页，页数可能显著增加。

模板风格锁定在两种模式下都有效。用户要求沿用企业样式，不应自动被解释为要求全文铺进正文。

## 8. 企业用户需要准备什么

| 材料 | 用途 |
|---|---|
| 可编辑的原始 PPTX | 导入版式和资产；尽量避免将可替换标题全部转曲或做成图片 |
| 模板原始效果的 PDF 或截图 | 对照导入是否丢字体、图形和布局 |
| Logo 与品牌固定图片 | 明确哪些永远固定，哪些允许替换 |
| 品牌色规范、可用字体或指定替代字体 | 建立企业语义色板和实际字体规则 |
| 页型说明 | 指定封面、目录、章节、正文、尾页及其用途 |
| 字段和固定文字说明 | 指定标题、序号、日期、汇报人、业务正文与品牌文案 |
| 正文自由范围 | 哪些框只换字，哪些允许换图、图表或企业组件 |
| 文稿及输出要求 | 摘要或全文、页数偏好、是否需要原生可编辑 PPTX |

可以先自动识别这些信息，再在模板管理里核对，不要求企业用户手写 JSON 或 Skill。

建议首批模板至少准备：封面 1 种、尾页 1 种、章节页 1–2 种、目录 1 种，以及正文的单栏文字、双栏对比、要点列表、图文、数据图表、阶段/排期等版式。具体数量由企业内容决定，不作为硬性门槛。

## 9. 验收与本次验证范围

### 9.1 建议的分阶段验收

1. **入库保真**：同一内容下对照原 PPTX 和导入 HTML，核对字体、图形、图片裁切、背景、母版继承和尺寸；记录已确认的降级项。
2. **固定页替换**：封面、章节、尾页仅授权字段变化；固定结构和品牌属性全部通过。
3. **正文受限变化**：文字、图片、图表和组件均位于授权区，实际字体和色彩符合允许集合。
4. **内容准确**：按选择的内容模式检查来源与覆盖；数字、单位、条件和图表数据保持一致。
5. **最终输出**：浏览器技术检查、视觉复核，以及 PPTX 在目标应用中的渲染对照。

截图相似度在固定渲染条件下可以重复计算，但新文案会改变大量像素，应遮罩可变区并作为辅证，不能用单一截图分数替代固定项与内容检查。
