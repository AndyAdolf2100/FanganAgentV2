# 项目截图复核适配

来源：118研究第18–20轮（2026-09-28）；工具行为与通用建议已分开归档。此文件是本项目新增适配，不是远端已有独立skill。

1. 全页render_probe先检查资源、碰撞、容量与对比度。
2. 每次仅1张成品PNG送项目的understand_image能力，附主题、角色、准确页号及文字风格分析。不要同时附模板截图或风格参考图，避免模型误把参考图当成成品。参考图在设计阶段单独分析。
3. 每页返回实际观察、问题、严重程度和修改建议。机器通过不能替代审美通过；配图未成功不能声明视觉目标完成。
4. 主Agent读取实际问题和此前失败记录，选择repair_page工具及具体参数；最多2轮、每轮3页，先筛中高优先级再选页，只改CSS和构图。text_catalog锁定所有文字与数字，宿主校验全文和图片引用。
5. 修版后再跑探针、全册一致性与看图；截图复查也每次仅1页，修改多页时依次分别请求。全册失败恢复上一版。完整过程保留tool-trace和visual-review报告。
6. 未审/未审完/待修/缺图/通过分别报告。预算耗尽或视觉响应遗漏页面不得算通过。

当前限制：采用全册首次渲染后逐页看图；尚未实现118建议的每生成一批就即时调整后续页面。图表修版仍保留原生结构，本轮只记录建议。每次页面修复最多2次HTML尝试，探针失败自动反馈。原稿、数字、来源及备注不能删除；审查建议与锁文案冲突时，主Agent转为布局/层级修复。低优先级偏好保留在报告，不能冒充高危问题。累计图片与视觉预算统一控制，历史预留不清零。
