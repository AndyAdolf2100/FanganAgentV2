# 企业 PPT 生成、优化中的对话

企业工作流 v5 的项目页面新增「和 Agent 一起优化 PPT」面板，运行中也可发送意见，例如「第 8 页圆环放大，让标签保持一行」。可另填页码 `8,13-15`；留空则由项目 GLM 结合提交时的页面信息判断。普通网页 PPT 流程保持原样。

## 处理路径

1. 前端提交文字、可选页码、当前任务 ID 和去重消息 ID。后端先保存消息与页面身份，立即返回收件状态；网络重试不会重复发起同一修改。
2. 运行中的任务在模板或页面组处理后的安全节点调用项目 GLM。问题得到文字答复，修改意见得到明确计划；页面未齐时可等待后续节点。系统通知和模型答复在界面分别展示。
3. 实际修改在当前调度批次所有视觉请求结束后认领；同组意见合并后走原有模型完整 HTML 生成、来源/品牌检查、浏览器检查和单图 Seed 复查。
4. 修改过的页重新审查，未改页复用版本及审查条件匹配的证据。修改计划不能当作完成；只有新候选实际提交、逐项复验通过才标记该请求完成。整套 PPT 的交付仍须经过原有完整门禁。
5. 已结束的任务可通过对话继续优化原任务，保留页面版本和产物历史。终审时晚到的消息也会续接；一次执行最多处理三批，后续请求继续排队。任务失败不会无限重启付费修复；服务重启或版本切换后，旧意见标明需重新确认。

GLM 页面生成与任务执行仍串行；Seed 单图审查共用最多五路的视觉池。对话理解也走同一工作线程，因此长时间模型调用期间不会立即得到模型回复，但消息可以提交和持久保存。

## 范围与证据

- 当前功能支持企业模板 v5，调整既有文稿的排版。更换文稿、企业主题或解除品牌锁不属于此入口。
- 对话理解节点读取文字、状态和页面身份，没有直接接收截图；具体视觉判断仍由原工作流的 Seed 完成。
- 指定页在发送时绑定稳定页面 ID、来源组和版本，避免续页变化后改错页；自然语言引用页码时给模型提供提交时的目录。
- 已失败任务可以先与项目GLM讨论。若优化任务尚无 `revision-state.json`，对已有页的修改计划会保留，界面提示点击「继续当前任务」；点击后在同一任务补页和验收，不能把计划当作已经修改成功。
- 等待用户点击续跑的修改计划在服务重启后仍保持待执行；重启不会自动发起生成。已有版本切换或来源改变时则重新确认，避免把旧意见套到新稿。
- 局部要求完成与整册交付状态分开展示。失败候选保留日志，不覆盖已提交草稿。

## 验证边界

服务、API、队列竞态、页面身份绑定及修复接入用离线模型替身回归；前端使用真实 Vue 组件和浏览器，接口拦截。该验证不消耗 GLM/Seed 额度，不等于已验证真实模型对每项自然语言要求的理解和美化效果。
